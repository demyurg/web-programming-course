# Данные и API учебного тренажёра

Версия формата: 1. Контракт одинаков для всех этапов курса. [Базовый учебный модуль](data/training-set.json) используется с начала курса; для A6 опубликован также [повышенный учебный модуль](data/training-set-advanced.json).

## Модуль и задания

В пользовательском интерфейсе **модуль** — это тематическая коллекция учебных заданий. В текущем техническом формате модуль представлен структурой `TrainingSet`: она содержит `id`, `title`, `tasks`. Поэтому файл `training-set.json` — это один текущий учебный модуль, а `setId` в API — его технический идентификатор.

Каждое задание содержит `id`, `kind`, `topic`, `prompt` и необязательный `code`. У `single-choice` есть `options`, массив объектов `{id,label}`. У `short-text` вариантов ответа нет. Идентификаторы уникальны в модуле и не зависят от порядка отображения. Строки `code` показываются как текст, не исполняются.

Студент самостоятельно описывает эти данные средствами TS на L1. `kind` имеет два значения: `single-choice` и `short-text`.

Ответ имеет один из форматов:

```json
{"taskId":"ts-1","kind":"single-choice","optionId":"b"}
```

```json
{"taskId":"react-1","kind":"short-text","text":"Моё объяснение"}
```

Пустая строка и строка только из пробелов считаются отсутствием текстового ответа. Перед отправкой клиент проверяет заполненность; сервер отклоняет такой `short-text` с `400 INVALID_ANSWER`. Сервер проверяет тип, принадлежность задания модулю и optionId списку вариантов. Для очистки уже сохранённого ответа используйте DELETE.

## Модуль и попытка

**Вариант ответа** — значение `optionId` внутри задания `single-choice`. Это ответ на отдельное задание, а не модуль для прохождения.

**Попытка** — одно прохождение модуля студентом: в ней хранятся ответы, статус и результат. Один модуль можно проходить несколько раз.

У каждого модуля есть собственные `id`, `title` и состав заданий. В A6 сервер возвращает список модулей, доступных участнику. По названию видно уровень сложности; условия заданий до начала попытки не возвращаются. Выбранный `setId` закрепляется за попыткой и не меняется при обновлении страницы. Учебный сервер предлагает два открытых модуля; контрольный может предложить каждому участнику свой список.

## Локальный сервер

Из корня репозитория, Linux и Windows PowerShell:

```sh
node course/server/server.mjs
```

Адрес `http://localhost:3001`. Сервер предоставлен преподавателем для A5–A6. Хранение попыток в памяти: перезапуск сервера удаляет их. Перезагрузка браузера при работающем сервере данные сохраняет. Для A6 открытый демонстрационный код — `DEMO-A6`; он не устанавливает личность пользователя. Учебный сервер не предназначен для официального тестирования.

## Маршруты

| Метод и путь | Тело запроса | Ответ |
| --- | --- | --- |
| GET /api/sets | — | `[{id,title,taskCount}]` — открытый каталог A5; на учебном сервере содержит базовый модуль |
| GET /api/sets/:id | — | `{id,title,tasks}` — открытый модуль A5; не раскрывает контрольные задания |
| GET /api/available-sets | —; заголовок `X-Access-Code` | `{sets:[{id,title,taskCount}],currentAttemptId}` — доступные модули и идентификатор последней попытки или `null` |
| POST /api/attempts | `{setId}`; в A6 также заголовок `X-Access-Code` | 201, Attempt; в A6 повтор для того же модуля при незавершённой попытке — 200 |
| GET /api/attempts/:id | — | 200, Attempt |
| PUT /api/attempts/:id/answers/:taskId | Answer, taskId совпадает с путём | 200, Attempt |
| DELETE /api/attempts/:id/answers/:taskId | — | 200, Attempt |
| POST /api/attempts/:id/submit | `{}` | 200, Result |
| GET /api/attempts/:id/result | — | 200, Result; 409 до завершения |

Пример ответа `GET /api/available-sets` на учебном сервере до начала попытки:

```json
{"sets":[{"id":"web-basics","title":"Основы веб-программирования — базовый модуль","taskCount":4},{"id":"web-advanced","title":"Веб-программирование — повышенный модуль","taskCount":3}],"currentAttemptId":null}
```

Пустой массив `sets` означает, что сейчас нет доступных модулей. Он не является успешным началом попытки.

Для A6 `POST /api/attempts` принимает `{setId}` и возвращает попытку выбранного модуля. Код доступа отличает этот запрос от A5: клиент передаёт `X-Access-Code` в **каждом** запросе к API контрольного прохождения. Контрольный сервер связывает код с участником, сроком доступа и его попытками. В учебном сервере код только демонстрационный; реальных участников и сроков он не ведёт. Код не помещается в URL или файлы проекта.

`Attempt` для A5: `{id,setId,status,answers}`. Для A6 добавляется `tasks` — задания выбранного модуля в закреплённом порядке, без правильных ответов. После выбора задания берутся из `Attempt.tasks`, а не из общего `GET /api/sets/:id`. `status` — `in-progress` или `submitted`; `answers` — массив Answer. В A6 повторное создание текущей незавершённой попытки того же модуля возвращает её с кодом 200; при уже идущей попытке другого модуля сервер возвращает 409. После завершения учебный сервер допускает новый старт, а контрольное прохождение ограничено одной попыткой. В A5 повторный POST создаёт новую попытку. PUT заменяет ответ этого taskId, DELETE удаляет его; повторное удаление допустимо. После submit изменение ответов возвращает 409. Повторный submit возвращает тот же результат, а не создаёт новую попытку.

`Result`: `{attemptId,status,score,maxScore,items}`; status `graded` или `pending-review`. Каждый item: `{taskId,status,score,maxScore,feedback}`, status `correct`, `incorrect`, `unanswered` или `pending-review`. score у ожидающего проверки ответа и у общего результата с ожидающими ответами равен `null`. maxScore — число заданий, по одному баллу за каждое. Пропущенный ответ получает 0; непустой short-text ожидает ручной проверки. Интерфейс показывает ожидание, не подменяет null нулём. Учебный сервер не предоставляет интерфейс ручного оценивания.

Ошибки: `{error:{code,message}}`; 400 — неверное тело, 401 — неверный или истёкший код, 403 — модуль недоступен участнику, 404 — объект не найден, 409 — действие не соответствует состоянию, 413 — слишком большое тело, 500 — искусственная учебная ошибка. Контрольный сервер проверяет принадлежность попытки участнику при чтении, изменении и завершении. Клиент проверяет `response.ok`: HTTP 400/500 сами по себе не отклоняют Promise fetch.

Для демонстрации ошибки добавьте к любому API-запросу заголовок `X-Demo-Fail: 1`: сервер вернёт 500 без изменения данных. При повторе уберите заголовок. Этот механизм существует только в учебном сервере.

## Необязательное локальное сохранение

A4 не требует черновик или восстановление после перезагрузки. Как необязательное расширение приложение может сохранять snapshot версии 1: `{version:1,setId,taskId,answers,status}`, где `status` — `in-progress` или `submitted`, а `setId` — технический id модуля. Если такое расширение реализовано, проверяйте версию и форму объекта, принадлежность `setId` текущему модулю, `taskId` и каждый `Answer` по заданиям модуля, а также допустимость статуса. Несовместимый snapshot нельзя принимать как корректную попытку или молча перезаписывать.

В A5 восстановление подтверждённой серверной попытки устроено отдельно: сохраните id, полученный в `Attempt.id`, как `attemptId`, затем запросите `GET /api/attempts/:id`. `attemptId` — только указатель на попытку, не копия её ответов. Если id отсутствует или сервер больше не находит попытку, клиент не может восстановить подтверждённое состояние; интерфейс должен объяснить это и предложить начать новую попытку. Учебный сервер хранит попытки в памяти и удаляет их при перезапуске. Сохранять весь неподтверждённый ввод отдельно не требуется. HTTP/API — способ обратиться к серверу, а не само хранилище.

При A6 повторное подключение с действительным кодом того же участника возвращает `currentAttemptId`, если попытка уже есть. Клиент может получить её через `GET /api/attempts/:id`. На учебном сервере это последняя попытка с демонстрационным кодом; после перезапуска сервера указатель снова равен `null`. При смене адреса API нельзя переносить на новый сервер код, идентификатор попытки и неподтверждённый ответ прежнего сервера.

## Учебный и контрольный режимы

Учебный сервер и его открытые данные используются при разработке. Официальные ключи, персональные коды и банк заданий не входят в этот пакет. Для аттестации преподаватель сообщает адрес совместимого сервера и выдаёт временный код; клиент меняет адрес в работающем интерфейсе. Контрольный сервер может ограничить повторное прохождение уже завершённого модуля. При техническом сбое преподаватель предоставляет резервный интерфейс. Клиент никогда не отправляет вычисленную им оценку как результат тестирования.
