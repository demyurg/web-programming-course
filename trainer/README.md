# Учебный тренажёр A5

Тренажёр загружает модуль с учебного сервера. После создания попытки можно отвечать в любом порядке, сохранять и очищать ответы, просматривать их в обзоре и отправлять попытку на проверку.

## Запуск

Из корня репозитория запустите учебный сервер:

```sh
node course/server/server.mjs
```

В другом терминале из папки `trainer/` запустите клиент:

```sh
npm ci
npm run dev
```

Откройте адрес, указанный Vite. Команды проверки клиента из папки `trainer/`:

```sh
npm run check
npm run build
```

## Данные попытки

- `src/App.tsx` загружает начальное состояние и показывает ошибку загрузки.
- `src/components/AttemptView.tsx` координирует действия и передаёт данные в список, карточку и обзор.
- `src/api/trainerApi.ts` выполняет запросы и проверяет HTTP-статус, форму данных и соответствие идентификаторов [контракту курса](../course/CONTRACT.md).
- `src/attempt.ts` содержит типы попытки и результата, правила редактирования и расчёт прогресса заполнения.
- `src/session.ts` хранит только `attemptId` под ключом `web-programming-course:trainer:attemptId` и восстанавливает попытку запросом к серверу.

В карточке кнопка «Сохранить ответ» отправляет PUT. Очистка из карточки и из обзора отправляет один и тот же DELETE. Серверный ответ заменяет подтверждённое состояние. Пока ответ не сохранён, его значение видно в карточке и обзоре с отметкой о несохранённых изменениях. Изменения хранятся в памяти вкладки, и их нужно сохранить до отправки попытки.

При перезагрузке клиент запрашивает подтверждённые ответы по `attemptId`. Если id отсутствует или сервер вернул 404, экран предлагает создать новую попытку. Итоговые баллы и статус приходят с сервера. `score: null` отображается как ожидание проверки.

## Самопроверка

1. Начните попытку, сохраните ответ с выбором и короткий текст. Смените вариант и снова сохраните. В Network проверьте PUT по тому же `taskId`.
2. Очистите ответ из карточки, затем из обзора. Проверьте DELETE, обновление обоих представлений и списка пропусков.
3. Для проверки ошибки добавьте к одному запросу сохранения заголовок `X-Demo-Fail: 1` средствами браузера. После HTTP 500 поле должно сохранить введённое значение и показать ошибку. Уберите заголовок и нажмите «Повторить запрос». После HTTP 200 должна появиться отметка о сохранении.
4. Перезагрузите страницу и убедитесь, что восстановились подтверждённые ответы. После перезапуска сервера убедитесь, что для старого идентификатора показано сообщение о недоступной попытке.
5. Сохраните короткий текст, отправьте попытку и проверьте тело POST `{}`, режим просмотра и статус ожидания проверки. Перезагрузите страницу и проверьте получение результата через GET.
