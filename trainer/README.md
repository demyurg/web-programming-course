# Учебный тренажёр: A1 и A2

Проект продолжает TypeScript-модель A1 и добавляет интерфейс React для одного учебного модуля.

## Запуск

Из папки `trainer/`:

```sh
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite. Проверка готовой сборки:

```sh
npm run check
npm run demo
npm run build
npm run preview
```

После проверки остановите сервер сочетанием Ctrl+C.

## Структура A2

- `src/domain.ts` — исходные типы и функции A1, без изменений.
- `src/data.ts` — два типизированных набора из A1; основной используется в интерфейсе, CSS-набор остаётся в демонстрации.
- `src/demo.ts` — демонстрация функций A1.
- `src/App.tsx` — название модуля, число заданий и единственное состояние выбора: строковый id.
- `src/components/TaskList.tsx` — список, получающий задания и callback через props; `task.id` служит ключом React.
- `src/components/TaskCard.tsx` — карточка задания из props; проверяет `kind` перед чтением `options` и выводит `code` как текст внутри `pre`/`code`.
- `src/styles.css` — адаптивная сетка и видимый фокус кнопок.

Для пустого модуля предусмотрен нейтральный экран. Если выбранный id отсутствует, список остаётся доступным, а вместо карточки появляется предложение выбрать задание. Кнопки работают через Tab, Enter и пробел. Ввод ответов, API и сохранение относятся к следующим этапам.

## Самопроверка

1. На старте видно первое задание, его код и три варианта.
2. Выберите задание React: карточка покажет условие и пояснение о текстовом ответе.
3. Вернитесь к первому заданию с клавиатуры.
4. Проверьте ширину окна 375 px: список и карточка располагаются друг под другом.
5. Для проверки пустого модуля передайте в `App` через prop `trainingSet` набор с `tasks: []`. Для отсутствующего id измените этот prop после выбора так, чтобы выбранного задания больше не было в наборе.
6. Выполните команды проверки выше. Демонстрация A1 должна по-прежнему показывать неизменность исходных данных и все сценарии прогресса.
