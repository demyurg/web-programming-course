# Отчет по проверке сценариев

**SHA коммита:** `69dc56fc5c18383c2d4c4871af25789ca0711ecf`

## Короткое описание сценариев проверки в `src/demo.ts`
1. **Поиск заданий:** Проверен поиск существующего id (`ts-1`) и отсутствующего id (возвращает `undefined`, чтобы ничего не упало).
2. **Фильтрация по теме:** Проверена регистронезависимая фильтрация для существующих тем (`typescript`, `react`), отсутствующей темы (`vue`) и пустого ввода.
3. **Расчет прогресса:** Проверен расчет для набора `web-basics` с массивом ответов, содержащим валидный выбор, строку исключительно из пробелов (не засчитывается) и ответ с чужим `taskId` (игнорируется). Также проверен пустой набор (результат 0 из 0).
4. **Чистота функций:** Через `Object.freeze()` и сравнение длин коллекций доказано, что функции не изменяют исходные данные.

## Ответы на вопросы
1. **Что возвращает поиск отсутствующего id?**  
   Возвращает `undefined` в безопасном режиме.
2. **Почему связь ответа строится через taskId, а не позицию?**  
   Индексы в массиве динамичны и могут измениться при сортировке, фильтрации или обновлении списка задач. Уникальный `taskId` обеспечивает жесткую логическую связь ответа и вопроса.
3. **Что считается заполненным текстовым ответом?**  
   Ответ, у которого текстовое поле после применения метода `.trim()` имеет длину больше 0 (строка из одних пробелов заполнением не считается).
4. **Чем compile-time-проверка отличается от проверки JSON во время выполнения?**  
   Compile-time проверка (TypeScript) валидирует типы и контракты в коде на этапе сборки. Runtime-проверка контролирует внешние динамические данные (JSON с сервера) в процессе работы программы, когда TypeScript уже скомпилирован в JS.
